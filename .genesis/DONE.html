1 · The Locked Spec (what we are building)

Cognitive job: For one PR's latest commit, produce a selective, grounded review: a short list of findings, each with file, line, evidence and confidence. Mechanical, high-confidence findings post automatically; uncertain, critical or irreversible judgements go to a human. (Until the confidence threshold is calibrated on the golden set, every finding goes to the human approval queue.)

Inputs: pull_request webhook or a member's /review comment; PR diff; code retrieved from the repo (hybrid semantic + exact-identifier search); repo memory (past reviews, conventions)  →  Outputs: one review on the PR, or one held in the approval queue; a commit status; a trace per review (retrieval, prompts/models, findings, cost, latency, confidence, human decisions, recovery)

Autonomy level: Level 3, human handles exceptions; level 4, human decides, for any CRITICAL finding. The bot comments only and never approves or merges. Effectively level 4 for everything until the threshold is calibrated.  |  Human-in-the-loop points: (1) overall confidence below threshold → approval queue; (2) any CRITICAL finding → escalate regardless of confidence; (3) developer dispute → dispute record, human rules, feeds evaluation; (4) draft/bot PRs and push bursts → only on a member's /review

Failure tolerance: zero tolerance for a confident, wrong posted finding (precision is the priority metric; target ≥ 90% on posted findings, threshold set after the golden set). Delay acceptable; silent loss not (WAL, DLQ, redelivery, sweeper)  |  Trust boundary: untrusted: all GitHub content (PR text, branch names, code, comments, fork PRs) AND all LLM output (schema-validated; every citation checked against code actually retrieved, else the finding is dropped). Trusted: repo config, secrets, golden-set labels

Filled during Genesis step G0 (Cognitive Design) via agentic-swe-master.

2 · Definition of Done (binary gates — checked by the VERIFIER, not the maker)

G4, 19 Oct 2026: gates lifted from the agentic-swe-master phase gates for the phases this project passes through, plus project-specific criteria from decisions/decisions-manifest.md.

2a · Universal (every milestone)

Dependency direction inward, zero cycles; matches context-graph.json edges (Phase 1, modular-architecture)
Every outbound call (LLM, embedder, GitHub, store) has an explicit timeout and a defined failure path (Phase 3/12, production-readiness)
All LLM output validated against the Finding schema before it is stored or shown (Phase 5, llmops)
Untrusted input handled per the trust boundary in §1: PR content never treated as instructions; LLM citations verified (Phase 11, security)
ruff check . clean AND pytest -q green (Python, chosen to reuse the memory project's provider layer, pacing and trace code)
No secrets or tokens in logs or traces; zero paid API calls unless config explicitly enables a paid tier (kickoff Q1, Q9)
One verify pass by a separate agent/model (L4). Maker is never checker.
No context-graph.json invariant violated: all five checked, not spot-checked

2b · Attached to specific milestones

Ingress (Phase 3/12): ingress failure matrix tests T1–T16 pass; T7, T8, T10, T12 also run against the baseline and both numbers recorded
Evaluation (Phase 9): golden PR set exists with labels written before any rung is scored (pre-registered); precision reported first, recall second; every rung scored on the same set
Retrieval (Phase 6): hybrid semantic + exact-identifier search; every finding cites retrieved code; context budget enforced
Specialists (Phase 4/8): 4 passes run in parallel with per-node timeout; a partial result (e.g. 3 of 4 done) is reported as partial, never as complete
HITL (Phase 19): approval queue, CRITICAL escalation and dispute path all work end-to-end; threshold set only from golden-set calibration (target ≥ 90% precision on posted findings)
Observability (Phase 10): every review has a trace covering retrieval, prompts/models, findings, cost, latency, confidence, human decisions and recovery (the brief's list)

2c · Kit gates that do not apply (recorded, not silently dropped)

Frontend (Phase 2): no dashboard UI planned; a static HTML trace/eval report replaces it. Revisit if the brief's "cost dashboard" is required for grading
Infrastructure / CI-CD (Phases 13, 18): local-only, zero cost; no cloud deploy or canary. Tests run locally; CI optional
