# ADR-0004 · One SQLite file instead of Redis + Tiger Cloud

- **Status:** accepted, 21 Oct 2026 (S3)
- **Evidence:** `.genesis/decisions/S3-database.md`, `FAILURE_MATRIX_01` §6

## Context
The baseline uses Redis (queue) and Tiger Cloud (vectors, events). Zero cost, nothing to administer, single machine.

## Decision
One SQLite file holds jobs, deliveries, the index (FTS5 + sqlite-vec), events and approvals. The atomic claim is a UNIQUE constraint inside one transaction per delivery.

## Consequences
Measured wins over the lecture design (ingress T7, T8, T10, T12). One writer at a time is fine at demo scale. Found mid-rung-3: one index file per repo, or rankings leak across repos (matrix 03, R12).
