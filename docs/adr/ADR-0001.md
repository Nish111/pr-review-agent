# ADR-0001 · Build evaluation first, then the system

- **Status:** accepted, 19 Oct 2026 (G5, `G5_DRAFT.md`)
- **Evidence:** `.genesis/PLAN.md`, `eval/findings_rung1-4.md`

## Context
The brief asks for a baseline-vs-upgraded story. Building features first and measuring last risks a system that can't be shown to work.

## Decision
Milestones run M0 spikes → M1 golden set → rungs 1-4 → M8 traces → M9 live demo. Every rung is pre-registered (`eval/PREREG_RUNG*.md`) and scored on the same golden set.

## Consequences
Every claim has a number and a committed method behind it. Cost: the live demo came last, so pipeline problems (key paths, webhook permissions) surfaced late.
